# AI-as-Me 记忆系统架构设计

## 概述

AI-as-Me 是一个基于 6 层递进式记忆架构的个人 AI 记忆系统，旨在构建一个能够理解、学习并模拟个人思维模式的智能助手。

## 记忆层级架构

系统采用数字编号命名，清晰展示记忆的递进关系：

```
00_Current (当前层) → 临时工作记忆
   ↓
01_Timeline (时间线层) → 事件记录
   ↓
02_Styles (风格层) → 习惯与偏好
   ↓
03_Mindset (思维层) → 决策框架
   ↓
04_Identity (身份层) → 核心价值观
   ↓
99_Intents (意图层) → 当前目标与约束
```

---

### 00_Current: 当前工作记忆
**定义**: 当前会话的临时工作空间，存储即时任务数据和活跃上下文。

**特征**:
- **生命周期**: 单次会话或临时任务
- **易失性**: 会话结束后需要提炼或丢弃
- **容量**: 不限，但应定期清理

**输入源**:
- 当前对话内容
- 临时文件和草稿
- 会话中的待办事项
- 实时计算结果

**输出目标**:
- 会话结束时提炼至 `01_Timeline`
- 临时文件归档或删除

**存储格式**: Markdown, JSON, 临时文本文件

**目录结构示例**:
```
00_Current/
├── session_2026-01-01.md
├── temp_notes.md
└── active_tasks.json
```

---

### 01_Timeline: 时间线记忆
**定义**: 近期事件、对话摘要、项目进展的时序记录。

**特征**:
- **生命周期**: 近期（1-3个月）
- **按时间组织**: 年/月/日分类
- **可检索性**: 通过时间、主题检索

**输入源**:
- `00_Current` 的会话摘要
- 项目里程碑记录
- 重要事件标记
- 日常互动记录

**沉淀机制**:
- **升级至 02_Styles**: 当某个模式/习惯在 `01_Timeline` 中出现 **3次或以上** 时，自动提示升级至 `02_Styles`
- **归档**: 超过 3 个月的记录可归档

**输出目标**:
- 重复出现的模式 → `02_Styles`
- 深刻的思维见解 → `03_Mindset`

**存储格式**: Markdown (按日期组织)

**目录结构示例**:
```
01_Timeline/
├── 2026/
│   ├── 01-January/
│   │   ├── 2026-01-01.md
│   │   └── 2026-01-15.md
│   └── 02-February/
└── archive/
```

---

### 02_Styles: 风格与习惯层
**定义**: 稳定的工作习惯、沟通风格、工具偏好和操作流程。

**特征**:
- **生命周期**: 中期（3-12个月）
- **可操作性**: 直接影响 AI 的行为模式
- **可配置**: 支持 YAML/JSON 格式化配置

**输入源**:
- `01_Timeline` 中出现 ≥3 次的模式
- 明确声明的工作偏好
- 工具使用习惯
- 沟通风格分析

**沉淀机制**:
- **升级至 03_Mindset**: 当某个风格被长期稳定使用（≥6个月）且具有普适性时，升级至 `03_Mindset`
- **修正**: 允许人工或 AI 建议修正不再适用的习惯

**输出目标**:
- 稳定的决策框架 → `03_Mindset`
- 过时的习惯 → 归档或删除

**存储格式**: YAML, JSON

**示例文件**:
```yaml
# 02_Styles/communication.yaml
preferred_tone: "简洁、直接"
response_length: "中等"
emoji_usage: false

# 02_Styles/work_habits.yaml
task_breakdown: true
documentation_level: "详细"
code_style: "functional_programming"

# 02_Styles/tools.yaml
editor: "VS Code"
terminal: "zsh"
version_control: "git"
```

---

### 03_Mindset: 思维模型层
**定义**: 思维模型、决策框架、知识结构和专业领域的抽象理解。

**特征**:
- **生命周期**: 长期（1年以上）
- **抽象性**: 超越具体事件的通用原则
- **结构化**: 形成知识图谱

**输入源**:
- `02_Styles` 中稳定且普适的习惯
- 明确表达的思维框架
- 专业领域的知识沉淀
- 决策树和推理模型

**沉淀机制**:
- **升级条件**: `02_Styles` 中的某个记忆稳定运行 ≥6 个月，且具有跨场景适用性
- **验证**: 需要与 `04_Identity` 一致性校验
- **修正**: 允许基于新认知进行迭代更新

**输出目标**:
- 核心的、不可变的原则 → `04_Identity`（需人工确认）

**存储格式**: Markdown, YAML (结构化知识)

**示例文件**:
```yaml
# 03_Mindset/decision_frameworks.yaml
problem_solving:
  - "定义问题"
  - "分解子问题"
  - "寻找模式"
  - "验证假设"

priority_matrix:
  urgent_important: "立即执行"
  not_urgent_important: "计划安排"
  urgent_not_important: "委托或自动化"
  not_urgent_not_important: "删除"

# 03_Mindset/knowledge_domains.yaml
expertise:
  - "软件工程"
  - "系统设计"
  - "产品思维"
  - "认知心理学"
```

---

### 04_Identity: 核心身份层
**定义**: 系统的"宪法"（Constitution），包含核心价值观、性格特征、人生信念。

**特征**:
- **最高优先级**: 所有决策必须符合 `04_Identity`
- **唯一修改权**: 仅限人工修改
- **不可妥协**: AI 不得建议违反此层的行为
- **生命周期**: 永久（除非人工修改）

**输入源**:
- 人工填写
- `03_Mindset` 中经过长期验证的核心原则（需人工确认）

**核心文件**: `constitution.yaml`

**内容结构**:
```yaml
name: "User"
core_values:
  - "诚实与透明"
  - "持续学习与成长"
  - "追求卓越而非完美"

personality_traits:
  - "理性分析"
  - "同理心"
  - "长期主义"

decision_principles:
  - "优先考虑长期影响"
  - "拒绝零和博弈思维"
  - "保持开放心态"

boundaries:
  - "不做违反法律和道德的事"
  - "不传播未经证实的信息"

last_updated: "2026-01-01"
```

**校准逻辑**:
- 所有 AI 生成的建议必须与 `04_Identity` 进行一致性检查
- 若有冲突，AI 必须主动提示并拒绝执行

---

### 99_Intents: 意图与目标层
**定义**: 独立于记忆层级的目标管理层，存储当前的短期目标、规划和约束。

**特征**:
- **动态更新**: 随目标变化而调整
- **指导性**: 影响 `00_Current` 的任务优先级
- **边界性**: 定义当前阶段的行为边界

**内容**:
- `current_goals.md`: 当前的 Top 3 目标
- `constraints.md`: 对话中的绝对禁区和硬性要求
- `plans/`: 正在进行的项目计划

**与其他层的关系**:
- 读取 `04_Identity` 确保目标符合核心价值观
- 指导 `00_Current` 的任务优先级
- 影响 AI 在当前阶段的行为模式

## 记忆沉淀流程图

```
┌─────────────────┐
│  00_Current     │  当前会话
│  (临时记忆)      │
└────────┬────────┘
         │ 会话结束 / 任务完成
         ↓
┌─────────────────┐
│  01_Timeline    │  事件记录
│  (时间线)        │
└────────┬────────┘
         │ 重复出现 ≥3 次
         ↓
┌─────────────────┐
│  02_Styles      │  习惯与风格
│  (程序记忆)      │
└────────┬────────┘
         │ 稳定运行 ≥6 个月
         ↓
┌─────────────────┐
│  03_Mindset     │  思维框架
│  (语义记忆)      │
└────────┬────────┘
         │ 长期验证 + 人工确认
         ↓
┌─────────────────┐
│  04_Identity    │  核心身份
│  (宪法层)        │  ← 仅人工修改
└─────────────────┘
         ↕
┌─────────────────┐
│  99_Intents     │  当前目标
│  (意图层)        │  ← 动态更新
└─────────────────┘
```

**自动触发条件**:
1. `00 → 01`: 会话结束、对话超过 10 轮、完成重大任务
2. `01 → 02`: 模式出现 3 次以上
3. `02 → 03`: 稳定运行 6 个月以上
4. `03 → 04`: 仅限人工确认

## 六个文件夹的递进关系

### 记忆强度递进
```
00_Current  →  临时的、易失的
01_Timeline →  短期的、可检索的
02_Styles   →  中期的、可操作的
03_Mindset  →  长期的、抽象的
04_Identity →  永久的、核心的
99_Intents  →  动态的、指导性的
```

### 抽象层级递进
- **00_Current**: 具体事件（"今天讨论了 API 设计"）
- **01_Timeline**: 事件记录（"本周完成了 3 次 API 设计讨论"）
- **02_Styles**: 行为模式（"偏好 RESTful 风格的 API"）
- **03_Mindset**: 思维原则（"API 设计应优先考虑简洁性和可扩展性"）
- **04_Identity**: 核心信念（"追求简洁与优雅"）
- **99_Intents**: 当前目标（"本月完成 API 文档编写"）

### 修改权限递进
- **00_Current**: AI 自由创建和删除
- **01_Timeline**: AI 自动提炼，人工可编辑
- **02_Styles**: AI 建议，人工确认
- **03_Mindset**: AI 建议，人工审查
- **04_Identity**: **仅人工修改**
- **99_Intents**: 人工主导，AI 辅助

---

## 数据格式与可移植性

**格式标准**:
- 文本记忆: Markdown
- 结构化数据: YAML / JSON
- 时间戳: ISO 8601 格式

**可移植性保证**:
- 所有数据使用纯文本格式
- 支持 Git 版本控制
- 可在不同 AI 系统间迁移

---

## 维护与更新

**人工职责**:
- 定期审查 `01 → 02` 的自动提炼
- 手动编辑 `04_Identity`
- 清理过时的 `01_Timeline` 记录
- 更新 `99_Intents` 的目标

**AI 职责**:
- 自动提炼 `00 → 01`
- 建议 `01 → 02` 升级
- 与 `04_Identity` 进行一致性校验
- 根据 `99_Intents` 调整行为优先级

---

## 使用指南

### 初次使用
1. 填写 `04_Identity/constitution.yaml`（核心价值观）
2. 填写 `99_Intents/current_goals.md`（当前目标）
3. 开始对话，AI 会自动在 `00_Current` 记录
4. 会话结束后，AI 提示将内容提炼至 `01_Timeline`

### 日常维护
- 每周审查 `01_Timeline` 的新增记录
- 每月审查 AI 建议的 `01 → 02` 升级
- 每季度更新 `99_Intents` 的目标
- 每年审查 `04_Identity` 是否需要调整
